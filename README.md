# Codex Reset

**Лимиты Codex, уведомления и авторесет — в своём Telegram-боте.**

[![Checks](https://github.com/giveuper39/codex-reset/actions/workflows/checks.yml/badge.svg)](https://github.com/giveuper39/codex-reset/actions/workflows/checks.yml)
![Python](https://img.shields.io/badge/Python-3.10%2B-3776AB?logo=python&logoColor=white)
[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)

Персональный бот, который каждый размещает на своём VDS или компьютере.
Показывает остаток лимитов, следит за появлением banked reset и применяет
разрешённый ресет перед сгоранием. Один бот, один владелец, один аккаунт Codex.

[Установка](#установка-на-vdsvps) · [Локальный запуск](#локальный-запуск) · [Управление](#управление-в-telegram) · [Ввод токена с телефона](docs/phone-setup.md)

> [!IMPORTANT]
> Авторесет работает по **конкретному `creditId`**. Выбранный ресет должен
> сгорать раньше остальных. Неполные данные или неоднозначный выбор
> блокируют применение.

## Возможности

- Статус недельного и пятичасового лимита с временем следующего обновления.
- Уведомления о новых banked reset, обновлении лимита и приближении сгорания.
- Вход в Codex через официальную страницу с одноразовым кодом.
- Разрешение автоприменения отдельно для каждого ID.
- Кнопка включения и паузы авторесета, отдельный переключатель уведомлений.
- Сохранение настроек, состояния и очереди уведомлений после перезапуска.

Python 3.10+, стандартная библиотека и Codex CLI. Запросы к модели не выполняются.
Обычная работа использует исходящие HTTPS-соединения: домен и входящие порты не нужны.

## Установка на VDS/VPS

Для Ubuntu/Debian с systemd:

```bash
sudo apt-get update
sudo apt-get install -y python3 git curl bubblewrap

git clone https://github.com/giveuper39/codex-reset.git
cd codex-reset
sudo bash install.sh
```

Установщик создаст отдельного пользователя `codex-reset`, установит Codex CLI
и попросит **токен вашего бота из [@BotFather](https://t.me/BotFather)**.
Ввод токена скрыт; конфиг сохраняется с правами `600`.

После установки:

1. Откройте одноразовую ссылку, которую напечатал установщик, и нажмите **Start**.
   Это привяжет ваш Telegram-аккаунт как единственного владельца.
2. Нажмите **«Подключить Codex»**, откройте официальную ссылку и введите код.
   В настройках безопасности ChatGPT должен быть разрешён device code login.
3. Откройте **«Banked resets»** и разрешите нужные ID.
4. Нажмите **«Включить авторесет»** и подтвердите список.

Свежая установка запускается с приостановленным авторесетом.
Уже существующий вход Codex того же пользователя хоста подхватывается автоматически.
Сервис работает после выхода из SSH и запускается при загрузке сервера.

```bash
sudo systemctl status codex-reset-bot --no-pager
sudo journalctl -u codex-reset-bot -n 40 --no-pager
sudo systemctl restart codex-reset-bot
sudo systemctl disable --now codex-reset-bot
```

## Локальный запуск

Установите [Codex CLI](https://learn.chatgpt.com/docs/codex/cli) и Python 3.10+,
затем из папки проекта выполните:

```bash
python3 configure.py
python3 codex_bot.py
```

Настройка попросит токен и покажет ссылку для привязки владельца.
Далее аккаунт подключается кнопкой в Telegram.

На Windows используйте `python` вместо `python3`. Нестандартный путь к CLI:

```bash
python3 configure.py --codex /absolute/path/to/codex
```

Компьютер должен оставаться включённым. На Windows npm-обёртка автоматически
разрешается в нативный `codex.exe`.

## Управление в Telegram

| Команда / кнопка | Действие |
| :--- | :--- |
| `/start`, `/status`, «Статус» | Лимиты, сроки и состояние переключателей |
| `/resets`, «Banked resets» | Список ресетов и разрешение конкретного ID |
| `/connect`, «Подключить Codex» | Вход через device code |
| «Включить авторесет» | Подтверждение разрешённых ID |
| `/pause`, «Приостановить авторесет» | Пауза применения; мониторинг продолжается |
| «Уведомления» | Включение и выключение обычных уведомлений |

Все даты показываются в **UTC**. Переподключение аккаунта приостанавливает
авторесет и очищает разрешения. Новый banked reset сам не получает разрешения:
бот присылает уведомление с кнопкой для его подключения.

## Правила авторесета

| Условие | Значение |
| :--- | :--- |
| Проверка статуса | Раз в 60 секунд |
| Срок применения | Последние 15 минут до сгорания |
| Остаток основного лимита | Не учитывается |
| Выбор | Ближайший будущий `expiresAt` из полного списка |
| Разрешение | Отдельно для каждого ID + общий переключатель |

Перед запросом проверяются срок сгорания, весь список ресетов и поддержка
`creditId` установленным CLI. Запрос всегда содержит точный ID. Если более ранний
ресет не разрешён, более поздний не будет использован вместо него.

ID и `idempotencyKey` сохраняются **до** запроса. Сетевые повторы относятся
к той же попытке. После успеха проверяется исчезновение выбранного ID
и сохранность остальных. Подтверждённое списание больше не повторяется.

Если API показывает уменьшение расхода без установленной причины, бот сообщает
именно об изменении расхода. Первый снимок устанавливает исходное состояние,
а уже доступные ресеты не объявляются новыми.

## Файлы и ограничения

<details>
<summary><strong>Где хранятся данные</strong></summary>

| Данные | Путь |
| :--- | :--- |
| Токен бота и конфиг | `~/.config/codex-reset-bot/config.json` |
| Состояние и разрешения | `~/.local/state/codex-reset-bot/bot.json` |
| Журнал безопасных повторов | `~/.local/state/codex-reset-bot/redemptions/` |
| Программа на VDS | `/opt/codex-reset/` |
| Домашняя папка сервиса | `/var/lib/codex-reset/` |

Сохраняйте конфиг и журнал повторов вне Git и переписок. Повторно показать
ссылку владельца можно через `configure.py --show-owner-link`; после привязки
она не даёт другому аккаунту доступ к управлению.

</details>

- Остаток лимита не влияет на попытку применения. Если сам Codex вернёт
  `nothingToReset` или `noCredit`, бот уведомит владельца и повторит проверку
  до сгорания выбранного ID. Результат применения определяет сервис Codex.
- Серверу нужны сеть, верные часы и действующий вход Codex. Работа в последнюю
  секунду не гарантируется; окно в 15 минут оставляет время для повторов.
- Пауза не отменяет уже отправленный запрос. Подтверждённое списание
  с незавершённой постпроверкой требует ручной проверки и приостанавливает авторесет.
- При потере ответа Telegram уведомление может повториться; повторное списание
  этим не вызывается. Сообщения об операциях и важных ошибках остаются включены.

## Проверки

```bash
python3 -m unittest -v
bash -n install.sh
```

Тесты проверяют привязку владельца, права доступа, точный выбор ID, условия
применения, уведомления, сетевые повторы и приоритет ответов на кнопки.
GitHub Actions запускает их на Python 3.10 и 3.13. Реальное списание в тестах
не выполняется. Транспорт Telegram сначала использует IPv4, с IPv6 как запасным
вариантом, чтобы недоступный IPv6-маршрут не задерживал каждую кнопку.
